# Post-S1 T6 host-binding lifecycle

## Classification

`HOST_SPECIFIC_DERIVED_BINDING` is execution state, not scientific authority.
It binds the registered T6 Fold-3 train/validation population and immutable
scientific input identity to one parity-verified runtime input locator.

## Required lifecycle

- The binding need not pre-exist on a new host.
- The runner must validate an existing binding, including its SHA256 sidecar.
- A missing binding, or one stale only in canonical code/runtime realization,
  must be deterministically regenerated from registered authorities.
- A different scientific input authority, T6 population, Fold-3 role set, or
  outer/test role fails closed and must not be regenerated by substitution.
- Scientific identity is stable across equivalent verified locators. Runtime
  realization records the actual root, code SHA, parity population, and R64,
  R128, or R160 resolution.
- Generated bindings are atomically written and manually patching historical or
  host bindings is forbidden.

## Operational boundary

The post-S1 runner receives explicit canonical code SHA, host-binding output
path, verified media root, and RGB source root. It may materialize only the
registered T6 inner population. No outer/test rows, source retransmission,
backbone, H5, posture, or other scientific family enters this lifecycle.
